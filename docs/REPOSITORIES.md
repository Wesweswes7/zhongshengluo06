Create learning repositories as actual material becomes available. The repository table in the Profile README is explicitly a roadmap, not a claim that all seven repositories already exist. Pin the strongest real work rather than filling every available slot.

Each repository should provide:

1. README: purpose, current state, contents, author contribution, and links.
2. Documentation: a `docs/` directory or a linked documentation section.
3. Showcase: selected notes, experiments, or projects with real links and results.

Code projects should add environment requirements, data access instructions, reproducible run steps, expected output, and limitations. Reading repositories can use an annotated index as their showcase. Add only the directories required by actual content.

Use the website for concise research context and the repository for technical detail. Keep each long-form note in one primary location and link to it from the other. The website and profile need a short manual synchronization when identity, skills, or selected work change.

ML topic notes belong primarily in `machine-learning-notes`; course indexes should link to them. Computational social science projects belong primarily in the repository representing the question, with technical topics as tags. Do not duplicate a project into several repositories to fill categories.

Before publishing photos or third-party materials elsewhere, keep their reuse permissions distinct from any code license. No open-source license has been selected for the supplied personal photograph.
